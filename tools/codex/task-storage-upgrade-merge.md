1. **Data** (copy from `tools/gemini/out/...` into `Resources/Data/`, trimming to what the code reads; unknown fields rejected like the existing catalogs): `materials.json` (17 materials incl. `chi_ton_ngoc_tuy` with `pvpOnly`), `upgrade_costs.json` (per copy rarity × Trọng step: material tier + count by item type group, catalyst count, Bạc), `merge.json` (steps with `silver`, `extraMaterials`), `rewards.json` (only what task needs: offline PvE win/loss/first-clear). 3. **Pure C# services in `Scripts/Economy/`** (no UnityEngine), each returning a result object with a Vietnamese error message, atomic (all-or-nothing):
   - `UpgradeService`: cost preview for Trọng n→n+1 of a copy (by item type group, copy rarity, step), can-afford check, apply. Max Trọng 9. Show which Đột Phá unlocks at 3/6/9 (read the item's `unlocks` from ItemCatalog data via an interface so tests can fake it).
   - `MergeService`: validate (2 different uids, same itemId, same rarity, both ≥ Trọng 3, not `supreme`), preview (output rarity, output Trọng = clamp(floor((a+b)/3), 2, 7), Bạc, extra materials such as 5 `chi_ton_ngoc_tuy` for legendary→supreme, 50% refund of the materials spent upgrading BOTH inputs from Trọng 1 minus the cost of the output's Trọng at the output rarity — never negative), a `weakerThanBestInput` flag (compare tierMultiplier×rarityMultiplier of output vs the stronger input), apply (removes both inputs, also from the loadout; adds the output copy).
   - `SellService`: price per economy doc (base price by rarity + share of Bạc/materials invested); removes from loadout.
   - `RewardService`: rewards for an offline battle result (win/loss) from `rewards.json` — Bạc, materials (seeded by the battle seed so it is deterministic), hero EXP only if the data has it.
